# 인증/회원 관리 — 추후 개선 메모

Issue #8에서는 관리자·본인 중심의 최소 기능을 구현했습니다.
아래 항목은 **이번 Issue 범위 밖**이며, 이후 별도 Issue로 진행하면 됩니다.

## 현재(Issue #8) 동작

- 본인 비밀번호 변경: `PATCH /members/me/password` (`current_password` + `new_password`)
- 관리자 비밀번호 초기화: 고정 임시 비밀번호(방식 A)로 리셋 후 응답에 안내
- 이메일 발송 없음 (관리자가 오프라인으로 안내하거나 응답의 임시 비밀번호를 전달)

## 추후 개선 후보

### 1. ID 찾기

- 이메일 또는 학번으로 `login_id` 조회
- 응답 시 아이디 일부 마스킹 (예: `hon***`)

### 2. PW 찾기 (셀프 재설정)

- 이메일 인증 코드 또는 재설정 링크(토큰)
- 토큰 만료 시간, 1회용 처리
- SMTP / 외부 메일 서비스 연동
- 환경 변수로 메일 설정 관리 (`.env`는 깃에 올리지 않음)

### 3. 관리자 비밀번호 초기화 고도화

- 방식 B: 서버가 랜덤 임시 비밀번호 생성 후 응답(또는 메일)으로 1회 전달
- 방식 C: 관리자가 Request body로 `new_password` 지정
- 초기화 후 다음 로그인 시 비밀번호 변경 강제 (`must_change_password` 플래그 등)

### 4. 사용자가 스스로 바꾸는 UX

- 로그인 후 마이페이지에서 비밀번호 변경 (이미 `PATCH /members/me/password`로 API는 존재)
- 초기화 직후 강제 변경 플로우와 프론트 연동

## 참고

- 임시 비밀번호 문자열을 md/이슈에 하드코딩해 두지 말 것 (코드 상수·환경 변수로 관리)
- 시크릿(`.env`, 실제 운영 비밀번호)은 저장소에 커밋하지 말 것
